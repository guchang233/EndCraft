# 实现状态与继续接入条件

## 用户目标

在真实《终末地》的场景里操控史蒂夫式角色，使用 MC 的九格快捷栏和库存，放置、破坏 MC 方块，并保留跳跃、鞘翅滑翔、烟花推进等 MC 机制。行走和飞行由 MC 模拟，宿主显示与世界交互需要实际接入。此目标尚未完成。

## 当前实机状态（第 15 版）

当前模块为 `endcraft.gameplay15`；旧玩法模块已停用。MC 位置经正常宿主 TeleportTo 转交，方块与角色以 HGRP/Unlit 进入场景绘制，HUD 最后绘制。原生管线与 ±90° 相机证据见 `reports/gameplay15-validation.md`。

网格与基础材质绑定后再切换原生材质，避免首次加载模型消失。更新时重新绑定 MeshFilter.sharedMesh，并通过 MarkDynamic 和 UploadMeshData(false) 通知原生管线。透明皮肤按 alpha≥128 裁成真实空洞，保留深度写入；未实现通用半透明排序。

桥接观察游戏自身的 Raw Input 读取，不注册新设备或消费输入消息。独立维护 yaw/pitch，以 quaternion 设置实际相机，俯仰范围 ±90°；前置第三人称朝向反转。第三人称从眼睛向相机做正常宿主射线查询，防止仰视时相机进入地下。

LocalPlayer 与单人 ServerPlayer 共用 SmoothTerrainCollision，跳过流入的地形体素，保留 MC 方块碰撞。当前地面上七组实际碰撞查询一致，24 项 Java 测试通过；仍需用户复验连续行走和其他地形。

第 10 版动作掩码与模型恢复证据仍为 `reports/gameplay10-restored.json`。关闭桥接只移除自己的 PlayerController 令牌并恢复原 Renderer 与 visual model；这些结果不证明所有菜单快捷键已隔离。

热更新带入原宿主锚点和 MC 位置，保留建筑坐标。第 15 版已配置下次启动自动开启桥接与项目 MC，但尚未重启验收该配置；跨场景与不同启动地点的建筑锚定仍待完善。

- 独立 MC 26.3 Fabric 工程：上游移动、射线、三角碰撞、代理实体、渲染导出及事件代码已保留，但未接入终末地宿主行为。
- 专用共享内存身份、协议版本、场景/碰撞 epoch、序列锁和心跳。诊断状态位于 0x40，不与上游数据区域重叠。
- 原生 Better-Endfield ABI 1 模块：方法解析、状态 RPC、只读相机线程观察、生命周期、断线状态与同名映射排他。
- 源码构建的精简 Host/XInput 加载入口、可回滚安装记录和认证本地 RPC 工具。
- MC 的显式 standby gate：宿主只发诊断心跳时，MC 不隐藏窗口、不接管输入、不自动创建镜像世界。
- 共享内存权限适配、句柄释放和同步读取锁；独立 C++/Java 两进程重连测试通过。
- 热加载的只读元数据检查模块、角色采样模块、角色到 MC 的诊断数据通路，以及有位移上限和自动恢复的移动接口试验模块。

## 当前实机记录

2026-10-06 首次加载器报告 `Host file was not found`；22:45 修复版已加载 Host，但该次实机未开启 RPC。22:57 部署项目内索引和路径日志。23:03 启动的真实游戏 PID 38460 已加载 Host 和诊断模块，认证 RPC 正常。旧版本结束前用户报告过一次未响应；现有证据不足以定位原因。当前版本运行后，用户确认转动视角、移动正常。

`reports/method-probe.json` 记录 11 个发现契约中的 10 个解析成功。元数据确认标准 `CharacterController.Move` 在当前类方法表中不存在；宿主自己的 `MovementComponent` 提供位置处理、胶囊扫掠和移动接口。方法解析成功不等于实际可用。

相机矩阵连续有效，FOV 为 58 度。用户移动和转动后，两次矩阵的最大元素差约 2395.17；投影矩阵保持相同。角色读数来自 `CameraManager.TailLateTick` 的实际游戏线程 37816：位置、速度、存活/过场标志和胶囊尺寸均已读到，当前角色胶囊高约 1.8、半径约 0.35 个宿主原始单位。

23:33 启动的新项目 MC PID 50544 实际收到上述角色数据，见 `reports/mc-received-host-actor.json` 和 MC 日志。新增槽位 0x900 使用版本、宿主 PID、序列锁、采样时间和有效标志。MC 拒绝过期超过 2 秒、未来时间、错误身份、写入中和非有限数据。该数据保持原始单位，不写入接管状态。

移动试验均在游戏线程执行，角色需静止、存活、非过场、着地且目标可行走；水平位移上限 0.05，观察 8 帧后恢复。角色变化或主动移动时停止恢复，避免拉回另一角色或用户。

| 接口试验 | 实机结果 | 证据 |
|---|---|---|
| `SetExternalPos(Vector3)` | 调用无异常，但立即和后续 8 帧位置均未改变 | `reports/motion-result.json` |
| `TeleportTo(Vector3, Boolean)` | 立即位移约 0.0499878，8 帧均位于目标，恢复误差 0 | `reports/teleport-result.json` |

第二参数的元数据名为 `showWarning`，试验使用 false。上述旧报告中的 `gameplay_modified` 仅跟踪写接口调用；验收采用轨迹读数。最新源码另列 `gameplay_write_invoked` 并用实际位移标记 `gameplay_modified`。短时间位置保持不能证明持续 MC 控制、鞘翅飞行或长期无纠正，也未验证服务端同步。

## 实机验收顺序

| 能力 | 通过证据 | 未通过时的处理 |
|---|---|---|
| 加载 | XInput marker、Host 日志、Host RPC ready | 记录 Windows 加载错误；不添加手工映射或绕过措施 |
| 双进程通信 | MC 实际 PID、持续心跳、状态序列递增 | 区分 MC 未启动、版本不符和宿主未加载 |
| 主线程相机观察 | 进入场景后连续有效矩阵，转动视角时矩阵变化 | 不启用输入或角色接管 |
| 角色控制 | MC 位置驱动宿主运动，连续移动无回弹、菜单退出恢复正常 | 保留未验证状态，不只写可见模型 Transform 冒充成功 |
| 画面合成 | 方块前后遮挡正确，横移/转身/跳跃对齐 | 按实测 Vulkan/D3D 路径适配；不把二维叠加当作深度合成 |
| 双向碰撞 | 玩家落在 MC 方块上、NPC 被阻挡、破坏后可通行 | 分别评估碰撞体与寻路，不能只证明玩家碰撞 |
| 战斗 | 剑/弓/TNT 改变宿主敌人的实际状态，敌人伤害反馈至 MC | 区分动画、客户端数值与真实敌人状态 |

持续位置转交、HUD、原生场景网格绘制和垂直相机已实现。本场景有场景深度与 UI 遮挡证据；其他场景、NPC 碰撞/寻路、宿主快捷键隔离、库存操作、鞘翅飞行和完整断线恢复仍需验收；宿主战斗流程尚未接入。

## 数据和单位

上游协议中的 `skyrimPid`、`SkyState` 等内部名称保留，但在本项目中表示宿主。通信坐标使用 MC 坐标，当前以 1 个宿主原始单位对应 1 个 MC 方块，Z 轴反射。上游 `70 units/block` 不用于终末地的位置映射。高度场尚不覆盖墙壁、洞穴和复杂立体地形。

CPU/共享内存开销、GPU 帧时间与重投影延迟只有在画面通路接入后才有可比测量值。当前诊断心跳年龄不是渲染延迟，也不是完整联动性能数据。
