# NeoForge 桥接性能

本轮优化针对桥接侧重复建模、直接内存分配和 GPU/队列等待。它不表示整个项目的性能问题已经解决，也没有可用于比较的终末地与 MC 联动 FPS 数据。

## 已修改

- 区块重建复用输出与单层临时网格。原先每个方块/流体的渲染层创建一个初始 64KB 的直接缓冲区；现在共享可扩容缓冲区。顶点三角化索引也复用，普通区块顶点省去不必要的 `Vec3` 分配。
- 玩家和动态场景复用批次网格及传输缓冲区；无效渲染类型使用空消费者，不再把最终被丢弃的顶点存入网格。渲染类型的纹理查询结果缓存，避免反复反射。
- 保留方块丢失后的恢复重发，使用最多 64MiB 的已生成区块快照，避免每四帧的静态区块恢复检查再次调用方块建模。方块/光照脏标记使对应快照失效；资源、世界、连接代次和预览模式变化清空缓存。缓存淘汰后仍可重新建模。
- 每帧区块建模最多两个区块，并在完成一个区块后检查 3ms 预算。这个预算不能中断正在建模的单个区块，复杂区块仍可能超过它。
- 方块动画图集用 PBO 和 GPU fence 异步读回，未完成时零等待返回。复用图集、其他纹理和脏图块的 CPU 缓冲区。首次纹理上传与其他动态纹理检查仍有同步读回，尚未消除所有 GPU 等待。
- 清空、初始图集及纹理渲染消息采用非阻塞发送，队列满时后续重试。队列积压达到容量一半时暂停新的网格捕获，保持选择数据更新，避免无意义地生成马上发送失败的动态网格。
- 光影预览只导出方块碰撞，不再导出被完整 MC 画面覆盖的方块可见网格或读回桥接纹理；切换回网格模式会清空并重新生成。
- Unity 宿主复用透明裁剪和顶点/UV/颜色/索引暂存数组。Unity 托管数组创建、网格上传及透明裁剪本身仍有开销。
- 透明纹理孔洞裁剪改用固定容量的栈上多边形，宿主复用透明区域工作区，省去每个区域四次裁剪中的临时堆数组。保持原来的透明阈值、插值和三角形顺序。
- 航空学物理体每帧在绘图区中心采样一次仿射变换：Sable 坐标变换反射调用由每顶点一次变为每艘物理体四次。顶点使用普通矩阵运算，绘图区保持双精度；每个方块保存独立偏移，避免临时方块坐标复用导致最后一个顶点错位。仍每帧重建方块并捕获方块实体动画，没有引入未经验证的物理体几何缓存。

缓冲区复用会保留各批次峰值容量；区块快照的 64MiB 限制针对当前保留的有效数据，直接缓冲区的物理释放仍由 JVM 管理。

## 验证与后续测量

完整构建与 57 项回归检查通过，覆盖网格重置、扩容后存储复用、区块快照所有权/淘汰/失效、渲染队列拥塞后的恢复，以及物理体旋转/缩放、远程绘图区坐标与逐帧移动。独立 MC 实机检查验证异步图集读回的 16 个已知 RGBA 字节与源数据完全一致、OpenGL 错误为零，普通及光影依赖组合均通过；切回网格模式后屏障粒子仍捕获 6 个顶点。原生宿主构建、输入及网格分层测试通过。

物理体优化在独立测试世界的 `EndCraft_PerfShip` 平台上核对：绘图区坐标约 20,481,032，17 个点的新旧算法最大差异约 `5.7e-15`，实际捕获 420 个顶点。测试使用 `render_test_ship`、`plot_transform_audit`、`render_audit` 操作；平台只创建于 `EndCraft-Render-Test`，不修改桥接存档。该小平台验证变换与捕获正确性，不等于大型物理体的 FPS 对比。

2026-10-13 的透明裁剪优化仅做离线检查，没有启动游戏：2,000 组固定种子的随机纹理、UV 与顶点颜色输入，与保留的原算法逐顶点字节比较完全一致；已有不透明保留、透明孔洞、面积和全透明检查也通过。16×16 透明棋盘格的 1,000 个三角形基准，预热后原算法约 107.0ms，新算法约 26.6ms，局部约快 4 倍。该数据只衡量裁剪 CPU 开销，不表示整体 FPS 提升。`tools/build-gameplay.cmd` 已包含这项离线检查；原生构建、F6 按键和网格分层检查均通过。

单独平坦测试世界的离线区块采样：预热 3 次后测量 10 次，普通客户端生成 3072 顶点的区块平均约 9.58ms；加载光影依赖的客户端，切回网格模式后约 5.81ms，光影预览只处理碰撞约 0.41ms。这些数据受运行环境与 JIT 预热影响，是不同路径的采样，不是优化前后比较，也不含宿主渲染和共享内存传输，不能换算成联动 FPS。

可复测：启动项目客户端并进入 `EndCraft-Render-Test` 世界，然后运行 `tools/test-neoforge-runtime.ps1 -Operation mesh_benchmark`。工具限定该测试世界及未连接桥接宿主的状态，结果记录于 `mc-neoforge/run/endcraft-neo-test.txt`。GPU 检查依次运行 `atlas_request`、`atlas_poll`，必须等待世界与资源加载完成。

后续重点是大型航空学物理体逐帧捕获、宿主透明裁剪/托管数组和真实联动场景的 CPU/GPU 时间。需要分别采集静止、移动、物品栏和大型物理体场景的帧时间及队列积压，再决定缓存、更新频率与协议改造。

Java 修改需重启 MC；宿主优化随 `endcraft.gameplay38.dll` 发布。本机已在终末地 1.6.3 中加载并建立 NeoForge 桥接，完成基础渲染和配件界面验证；仍无同场景优化前后的联动 FPS 对照，不能据此给出整机性能提升百分比。
