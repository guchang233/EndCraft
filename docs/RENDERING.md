# NeoForge 渲染与光影

桥接性能优化和测量边界见 [性能说明](PERFORMANCE.md)。

当前默认使用网格桥接：MC 导出方块和动态网格，终末地负责绘制及场景深度遮挡。第一人称手持物品、物品栏和 HUD 则由 MC 渲染成透明图片，再叠加到终末地。

## 本次修正

2026-10-15：当前开发宿主模块为 `gameplay38`。HUD/物品栏/第一人称已经是 MC 最终渲染的显示颜色，宿主上传 HUD 时使用线性标记纹理，使最终屏幕叠加直接采样这些字节，不再额外做 sRGB 解码。使用 `UI/Default` 自定义材质时保持白色 tint 与 alpha 1，保证不透明界面仍然不透明。`gameplay37` 实机抽查 62、85、139、198 四组不透明灰阶共 78,666 个像素，终末地和 MC 源图逐字节全部一致；38 保留该颜色路径。

TaCZ 的 Z 配件界面复用第一人称持枪渲染；网格桥接中打开该界面时临时切为第一人称，关闭时恢复原视角。该界面跳过原版暗色菜单背景，并单独使用全亮的预览光照，避免背景盖住先画出的枪械。普通第一人称仍使用原光照。TaCZ 仍是可选依赖，通过界面类名识别，不直接链接它的类。

`gameplay38` 在 MC 菜单打开时拦截 Unity `EventSystem.Update` 的 UI 事件派发，避免点击 MC 配件或 HUD 按钮时同时打开终末地菜单。直接读取新鲜的 MC 菜单状态，不依赖相机更新顺序；关闭菜单后继续拦截至鼠标松开并经过释放帧，再恢复原生 UI。此行为也覆盖分号关闭原生操作键独占的情况。EFML 的帧调度仍沿钩子链正常执行。诊断字段为 `native_ui_hook`、`native_ui_blocked`、`guest_screen_open` 和 `suppressed_native_ui_updates`。

车万女仆等 Mob 现在与玩家、船只共用原生三角面碰撞，避免只依赖粗体素支撑。临时真实女仆完成 120 次行走采样，移动 7.2 格，所有位置均有地面数据，最低脚底到地面间隙为 0；测试结束移除测试实体。玩家的现有女仆不做删除或传送。

- 跳过 MC 世界绘制时，仍处理客户端光照队列并重置世界漫反射灯光和 shader 颜色。否则上一帧物品栏的灯光状态会影响下一帧手持物品，区块光照更新也可能滞留。
- 透明图片由 GL 混合产生，读回后转换为直通透明度，避免 Unity UI 再乘一次透明度而使半透明边缘变暗。完全不透明像素不调亮。
- 捕获粒子图集与方块图集上的标准粒子，并修正相机相对坐标到玩家相对坐标的转换。屏障的红色标记、方块碎屑、烟等因此有了导出路径。屏障本体仍按原版规则不可见；标记由原版在满足手持等条件时产生。
- 动态网格支持 QUADS 和 TRIANGLES；文字字形使用字体纹理导出，不导出无纹理文字背景。其他无法捕获的渲染类型最多记录 32 种诊断，避免每帧刷日志。
- 粒子图集每 200ms 检查更新，其他已导出的纹理轮流检查，覆盖动态皮肤等纹理变化。像素读回保存并恢复 PBO 与像素步长，避免其他渲染模组遗留状态造成错位。
- 宿主保留动态透明网格的顶点颜色/透明度，并在 shader 支持时启用 `_UseVertexColor`。宿主 DLL 需要重新构建、在游戏关闭后更新并重启加载。

## 渲染覆盖范围

| 内容 | 默认网格桥接 |
|---|---|
| 普通方块、透明方块、流体、航空学物理体 | 已有网格路径 |
| 实体与方块实体的标准 VertexConsumer 渲染 | 已有路径，支持四边形与三角形 |
| 标准图集粒子、屏障标记 | 已补充路径；每帧最多 2048 个，距离 48 格 |
| 第一人称、HUD、物品栏 | MC 原生像素捕获 |
| 字体字形、F3+B 线条 | 字形纹理与线条几何 |
| 自定义 GL 粒子、程序化材质、额外纹理采样、特殊渲染阶段 | 网格协议不能完整表达；需要逐模组适配 |
| 光影包的阴影、反射、体积光、后处理 | 不能随普通网格导出；使用下面的预览流程验证 |

这是一份路径清单，不等于所有第三方模组均已完成视觉验收。

## 光影预览

优先验证用户提供的 `mc-neoforge/SHADER.zip`（Complementary Reimagined）。Iris 和 Sodium 为可选依赖，单独锁在 `mc-neoforge/shaders.lock.json`，默认启动不加载它们。

```powershell
# 独立 MC：加载 SHADER.zip，运行完整的 MC 世界/光影管线
.\tools\start-neoforge.ps1 -ShaderPreview -Offline

# 连接已加载 EndCraft 宿主的终末地，显示 MC 完整画面
.\tools\start-neoforge.ps1 -ShaderPreview -BridgeHost -Offline
```

脚本自动下载并校验可选依赖，将本地包复制到 `run/shaderpacks/SHADER.zip`，设置 Iris 配置。首次覆盖已有 Iris 配置时保存为 `iris.properties.endcraft-backup`。首次运行需要联网下载尚未缓存的依赖；`-Offline` 仅控制 Gradle。

可在游戏内切换：

```text
/endcraft render shader-preview
/endcraft render mesh
```

切换会通过 Iris API 启用/停用光影；没有安装 Iris 时，预览显示原版 MC 完整画面。普通启动器还可使用 JVM 参数 `-Dendcraft.renderBackend=shader-preview`，并自行安装锁定版本的 Iris/Sodium。

**预览会覆盖终末地原生场景。** 它用于验证 shader 编译、第三方模组渲染和完整帧读回，不是终末地场景与 MC 光影的最终融合。要让光影后的 MC 像素继续正确被终末地岩石、角色遮挡，还需要共享相机、深度与材质信息，以及宿主的深度合成路径；当前协议 12 尚未实现这些数据。

Sable 2.0.6 与 Veil 4.3.2 不接受 Sodium 0.6.13，要求至少 `0.8.12-alpha.2+mc1.21.1`。实验锁定 Iris 1.8.14-beta.1 与 Sodium 0.8.12。Sodium 的发行包使用外层服务加载器；ModDev 启动会误选外层包，脚本为开发运行提取原样嵌套 JAR 和外层支持类，普通启动器仍使用官方原始发行 JAR。光影包与这些依赖均不随 EndCraft 发行附件分发。

## 验证边界

本次原生宿主构建及输入/网格分层测试通过，NeoForge 完整构建与 57 项回归测试通过，覆盖透明度转换、三角形捕获及后续性能修正。

独立的 `EndCraft-Render-Test` 平坦世界已经实机进入：`SHADER.zip` 成功加载并显示天空、云和地形；Iris API 停用/启用光影两次切换均成功；屏障标记粒子实际捕获为 6 个三角形顶点，物品栏可正常打开。这里验证的是 MC 渲染及导出入口，尚未验证终末地最终画面。

用户提供的光影包包含 `BIOME_PALE_GARDEN`、`BIOME_SULFUR_CAVES`、`endFlashIntensity` 等本版本不存在的变量，Iris 跳过相关 uniform 并打印警告，其他光影继续运行。当前组合还使 Flywheel 从 `indirect` 回退到 `off`，不能据此保证机械动力全部渲染特效及性能；未修改用户提供的 ZIP。

此前离线修复不能证明最终颜色正确；2026-10-15 已在真实终末地 1.6.3 + NeoForge 会话中完成上述灰阶对比及女仆短程行走检查。`gameplay38` 已通过输入门控、菜单关闭释放、焦点切换、停用与 ABI 生命周期检查；NeoForge 构建和 58 项检查通过。实机配件界面和点击隔离的验证另记于本机 `reports/`。

38 版已在保留终末地进程的情况下加载，并正常保存、重启 MC。相同手枪配件预览的背景像素由 RGBA `(0,0,0,204)` 变为 `(0,0,0,0)`，枪身采样由 `(11,12,12,204)` 变为 `(63,64,68,255)`，宿主截帧可见正常枪械和场景。用户实测确认“亮度正常，点击不再穿透”。本机证据为 `reports/refit38-validation.json`、`refit-before38.png`、`refit-after38.png` 与 `refit-host-after38.png`。
