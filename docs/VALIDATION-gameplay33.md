# 第 33 版透明与流体修复

开发版，尚未发布。已安装并启用 `endcraft.gameplay33`，下次启动自动加载。按用户最新指示，本轮不更改分号输入逻辑。

## 实现

原渲染器把 MC 的透明方块与水交给不透明材质，并且没有处理 `REN_ATLAS_REGION` 动画消息。现按三角形标记分离实体、透明方块和流体；透明材质与不透明材质不再共享同一缓存项，MC 导出的颜色与透明度作为透明批次的材质颜色。

实机材质检查确认 `HGRP/Unlit` 提供 `_SurfaceType`、`_SrcBlend`、`_DstBlend`、`_ZWrite` 和 `_CullMode`。透明批次采用源 Alpha / 一减源 Alpha 混合，关闭深度写入，渲染队列 3000；实体批次写深度，队列 2000。模型仍交给宿主 HGRP 渲染，保留场景深度遮挡。玻璃保留实体碰撞，流体使用可选顶点标记 bit7，流体渲染网格不创建宿主实体碰撞体。协议版本和数据大小不变。

动画消息按区域更新纹理及 CPU 副本，同一渲染帧合并 Apply，避免每个小区域分别上传整张图集。水、岩浆及其他图集动画都使用此路径。区域尺寸和边界严格校验。

## 验证

- 用户放置普通玻璃、染色玻璃及水后回复“玻璃和水都正常”。
- 实机截图可见 MC 蓝色水面及其后的原生地面；运行诊断中透明／流体网格数从 24 增至 36，图集动画接收及上传计数持续增长。
- `active`、`guest_ready` 为真，桥接、场景渲染和绘制错误均为空；旧存档锚点保持一致。
- MC 构建通过，30 项测试全部通过；原生构建、透明／流体分层与颜色、动画区域行序及越界检查、模块生命周期检查通过。
- 项目 MC 通过正常退出完成保存，再启动新客户端加载流体标记，未终止游戏进程。

透明物体仍由宿主按渲染对象排序；复杂相交的大面积透明表面和水下效果未全面验收。透明批次使用三角形平均颜色，尚未实现完整的逐顶点光照。本轮未接入 MC 光影包、原生水面反射或折射，也未完成 TNT 炸原生岩石的校准。
