# 终末地伤害换算

2026-10-16，4.2.1 使用 `endcraft.gameplay39`。4.2.0 发行附件中的 `gameplay38` 仍使用旧算法。

## 规则

MC 计算武器、冷却、暴击、投射物与爆炸产生的命中伤害。宿主读取当前终末地角色的 `AbilitySystem.get_atk`，按下面的比例交给现有 `NewDamage / ApplyModifier` 接口：

```text
原生伤害输入 = MC 命中伤害 ÷ 5 × 当前角色攻击力 × damage_multiplier
```

倍率默认 1。相同角色、相同武器产生相同的伤害输入，计算不使用目标当前生命或最大生命；敌人的血量差异因而不会被百分比换算抵消。角色攻击力变化会影响后续命中。MC 代理的 20 点生命只是命中判定细节，不再作为敌人耐久标尺。

例如角色攻击力为 500、MC 命中伤害为 7 时，伤害输入为 700。仅按血量计算，1400、14000、140000 血的目标分别需要 2、20、200 次命中；这是公式示例，实际扣血和击杀仍需实机确认。

旧版计算为 `MC 伤害 × 目标最大生命 ÷ 20`，会让普通敌人与 Boss 的击杀次数接近，并导致高血量 Boss 承受巨额伤害。

## 调整倍率

在 EFML 的该模块配置中保留现有字段，添加或修改 `damage_multiplier`。范围为 0.01 到 100：2 为两倍，0.5 为一半。也可使用项目工具，保留当前锚点和启动器：

```powershell
python tools/configure-gameplay-startup.py --auto-start --module gameplay39 --damage-multiplier 1
```

无效倍率被拒绝，现有倍率不会被覆盖。角色攻击力无法读取、不是有限正数或伤害溢出时，不使用旧百分比算法兜底。状态报告的 `combat` 包含 `damage_model`、`damage_multiplier`、`mc_points_per_native_attack`、`last_player_attack`、`last_mc_damage` 和 `last_host_damage`。
